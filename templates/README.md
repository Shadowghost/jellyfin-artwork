# Artwork templates

Reference templates that define the global design standards for every
piece of generated artwork in this repository — borders, safe area,
aspect ratio, and the contrast targets a background colour must hit.

Open the SVGs in any editor to inspect the geometry; the constants
listed below match what the templates draw and what the generator
(`scripts/generate_thumbs.py`) writes into the produced files.

## Files

| File | Aspect | Pixel canvas | Safe area | Used for |
| --- | --- | --- | --- | --- |
| [`thumb.svg`](thumb.svg) | 16:9 | 1024 × 576 | 864 × 416 (inset 80 px) | `thumb.svg`, `backdrop.svg` |
| [`primary.svg`](primary.svg) | 1:1 | 1024 × 1024 | 832 × 832 (inset 96 px) | `primary.svg`, square logo cards |

The templates themselves are reference overlays — they are **not**
shipped to clients. The build pipeline only ships the per-studio
artwork files that follow these specs.

## Design standards

These apply to every produced artwork file regardless of aspect.

1. **Pixel canvas.** Longer dimension is exactly 1024 px. Pixel
   `width`/`height` attributes must match the `viewBox`; no
   user-space offsets on the root `<svg>`.
2. **Border.** A 1 px hairline along the canvas edge is permitted but
   optional. The visible "frame" the eye perceives comes from the
   safe-area margin, not from a drawn stroke. Do **not** add chunky
   decorative borders — they read as noise at small sizes.
3. **Safe area.** All non-background content (logo, type, marks)
   stays inside the safe-area rectangle. The inset is uniform on all
   four sides:
   - 16:9 thumb: **80 px** inset → 864 × 416 safe area
   - 1:1 primary: **96 px** inset → 832 × 832 safe area
4. **Logo placement.** Centred on the canvas, scaled to fit the
   safe area while preserving aspect ratio. Either dimension of the
   logo may touch the safe-area edge, but never the canvas edge.
   When the source paints its own canvas (built-in bg rect, gradient,
   etc.) the wrapper inherits that colour as the outer background, so
   the design and the canvas meet seamlessly at the safe-area edge.
5. **Background.** A single solid fill. Gradients, photos, and
   patterns are out of scope — they fight with the logo and break
   contrast checks.
6. **Contrast.** The background must reach **WCAG AA contrast
   (≥ 4.5:1)** against the logo's dominant ink colour. AAA (≥ 7:1)
   is preferred where the studio's palette allows it.

## Aligning an existing image to a template

Use this workflow when hand-authoring a `thumb.svg` or `primary.svg`
that is *not* generated by `scripts/generate_thumbs.py` (i.e. when the
entry in `studio.json` has `template: true` because it ships its own
custom layout).

1. **Start from the template SVG.** Copy `templates/thumb.svg` (or
   `primary.svg`) into the studio directory and rename it to match
   the artwork slot (`thumb.svg`, `primary.svg`).
2. **Delete the overlay elements.** Remove the grid pattern, the
   dashed safe-area rect, the crosshair, the rule-of-thirds dots,
   and the dimension labels. Keep the root `<svg>` with its
   `viewBox` and pixel dimensions intact.
3. **Set the background.** Replace the dark canvas `<rect>` with a
   solid fill in your chosen background colour. Verify WCAG AA
   contrast against the logo ink colour
   (see [Contrast targets](#contrast-targets)).
4. **Drop in the logo.** Paste the logo's drawable content (paths,
   shapes — not the surrounding `<svg>`/`viewBox`) into a `<g>`. Make
   sure none of the logo's elements rely on a `userSpaceOnUse`
   gradient anchored to its old coordinate system.
5. **Translate and scale to fit the safe area.** Let `(lx, ly, lw, lh)`
   be the logo's content bbox. Compute:

   ```
   scale = min(safe_w / lw, safe_h / lh)
   tx    = canvas_w/2 - (lx + lw/2) * scale
   ty    = canvas_h/2 - (ly + lh/2) * scale
   ```

   Then wrap the logo in
   `<g transform="translate(tx ty) scale(scale)">…</g>`.
6. **Sanity-check.** Render the file at 256 px wide. The logo should
   sit centred, its bounding rectangle should not cross the
   safe-area dashed line of the reference template, and the
   background should still pass contrast at the rendered size.

If your logo has both light- and dark-readable variants (some
studios ship a stacked dual-theme SVG), pick the variant whose
ink colour gives the higher contrast against your chosen
background and delete the other before placement.

## Contrast targets

Computed via the [WCAG 2.1 relative-luminance formula][wcag]:

```
sRGB → linear → L = 0.2126·R + 0.7152·G + 0.0722·B
ratio = (L_lighter + 0.05) / (L_darker + 0.05)
```

| Tier | Ratio | When |
| --- | --- | --- |
| AA  | ≥ 4.5 : 1 | Required — minimum any background must hit |
| AAA | ≥ 7.0 : 1 | Preferred — used when a brand colour or B/W can reach it |

If the source logo already paints its own canvas (a filled rect,
polygon, or rectangular path that covers the viewBox — including
gradients), the generator inherits that colour as the thumb
background so the design bleeds seamlessly to the edge. Detection
is done by rendering the source to a small bitmap and checking
that the perimeter samples agree on a consistent opaque colour and
that the interior is also mostly opaque.

Otherwise the generator scores candidate backgrounds by their
worst-case WCAG ratio against the logo's significant ink colours
and picks the highest, drawing candidates from:

1. Brand colours declared in `studio.json` under `colors[*].hex`.
2. White (`#FFFFFF`).
3. Black (`#000000`).

By construction one of white/black always passes for any
non-mid-grey logo.

## Generating thumbs from existing logos

Run from the repository root:

```sh
python3 scripts/generate_thumbs.py             # dry-run report
python3 scripts/generate_thumbs.py --write     # actually write thumb.svg
python3 scripts/generate_thumbs.py --aspect 1x1 --write   # 1:1 primary instead
```

The script walks `studios/*/studio.json` and processes every entry
where:

* `template: false` — explicit request, always processed.
* `template` missing AND the output file (`thumb.svg` /
  `primary.svg`) does **not** yet exist — bootstrap case.

If the field is missing **and** the output file already exists,
the entry is left alone — those are hand-crafted assets the
generator must not clobber. To force regeneration, pass `--force`.

For each match it:

1. Reads `logo.svg`, computes its content bbox and dominant ink
   colour (area-weighted average of fill/stroke colours).
2. Picks a background per the contrast table above.
3. Writes `thumb.svg` (or `primary.svg`) centred and scaled to the
   safe area.
4. Updates `studio.json`: adds the new artwork format to the
   `artwork` block and flips `template` to `true`, so the same
   entry is not re-processed on the next run.

Re-running is safe — anything already at `template: true` is left
alone. Pass `--force` to re-render existing entries (useful when
the template spec itself changes).

[wcag]: https://www.w3.org/TR/WCAG21/#dfn-relative-luminance
